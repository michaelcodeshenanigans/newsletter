# Weekly AI & Agentic Systems Digest — November 8–14, 2026

_2026-11-08 through 2026-11-14 · Revision 1_

This week tightened the production boundary around agent execution: AgentCore added direct web retrieval, changed its default runtime, and widened OAuth compatibility; MCP patched command-execution and confinement vulnerabilities; Google introduced a typed decision API; and OpenAI’s Agents SDK alpha expanded durable state, budgets, hosted tools, and Agent2Agent support.

## What changed

### AgentCore adds a direct Web Search API

**Status:** ga · **Event date:** 2026-11-10 · **Confidence:** high · **Score:** 21/21

**What changed:** The new InvokeWebSearch API returns ranked web results without requiring an AgentCore Gateway resource. Results include an extract and, when available, title, URL, and publication time; requests can filter by domain and publication time.

**Why it matters:** Applications can now use AgentCore’s raw web index directly instead of choosing between a Gateway MCP tool and a synthesized Web Answer response.

**Platform impact:** This creates a cleaner retrieval primitive for custom agent loops and evidence pipelines, while IAM, network access, audit events, source policy, prompt-injection handling, and downstream synthesis remain application concerns.

**Recommended action:** Run a frozen comparison of direct Web Search, Web Answer, and the current retrieval stack on source coverage, result freshness, injection resistance, latency, and completed-answer cost.

**Watchouts:** The launch is regional and usage-priced. Raw search results still require source-quality evaluation, content handling, and claim-to-evidence validation.

Sources: [src-01](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-bedrock-agentcore-web-search-api/)

### AgentCore Runtime V2 becomes the default for new runtimes

**Status:** ga · **Event date:** 2026-11-12 · **Confidence:** high · **Score:** 21/21

**What changed:** AWS changed the next-generation AgentCore Runtime from an explicit opt-in to the default for new runtimes in 19 Regions. Operators can select platformVersion V2 for migration or V1 to retain the previous generation for a new runtime.

**Why it matters:** A default change affects deployment assumptions even when teams do not start a deliberate migration project.

**Platform impact:** Runtime version must become an explicit infrastructure setting with startup, memory, image, concurrency, session-isolation, billing, and rollback tests. Existing runtime fleets will otherwise become mixed-version estates.

**Recommended action:** Inventory runtime versions, pin platformVersion in infrastructure code, and replay one production-like workload on V1 and V2 before migrating existing runtimes.

**Watchouts:** AWS reports sub-two-second P75 startup for a tested 2 GB image and up to 68% less billed memory for multi-turn agents; these figures are workload-specific vendor measurements.

Sources: [src-02](https://aws.amazon.com/about-aws/whats-new/2026/11/new-agentcore-runtime-default/) [src-03](https://aws.amazon.com/blogs/machine-learning/run-agents-securely-and-efficiently-with-the-next-generation-agentcore-runtime/)

### MCP reference servers v2.4.0 patch six vulnerabilities

**Status:** open source · **Event date:** 2026-11-11 · **Confidence:** high · **Score:** 21/21

**What changed:** Version 2.4.0 fixes six vulnerabilities across the filesystem, Git, and fetch reference servers. A high-severity Git flaw allowed an untrusted repository’s own configuration to execute a program during nominally read-only operations such as git_status; other fixes address filesystem races, repository-confinement bypasses, IPv6 SSRF filtering, and robots.txt path handling.

**Why it matters:** Read-only tool labels did not prevent process execution, showing that repository metadata and implementation behavior can cross the intended agent capability boundary.

**Platform impact:** MCP inventory and patching must cover server packages, host Git versions, filesystem semantics, network parsing, and trusted repository origins—not only gateway allowlists and tool descriptions.

**Recommended action:** Patch every affected MCP server, then add a regression using an untrusted repository with hostile Git configuration plus path, symlink, redirect, IPv6, and private-network cases.

**Watchouts:** The release documents residual Windows junction and race limitations. The filesystem package’s semantic version can also sort below older calendar-version packages, so upgrades should pin the exact patched version.

Sources: [src-05](https://github.com/modelcontextprotocol/servers/releases/tag/v2.4.0) [src-06](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-6hqx-gqrx-c5r2)

### AgentCore Identity adds OAuth 2.0 discovery URLs

**Status:** ga · **Event date:** 2026-11-13 · **Confidence:** high · **Score:** 18/21

**What changed:** AgentCore Identity can now use OAuth 2.0 authorization-server metadata URLs as well as OpenID Connect discovery URLs. Previously, authorization servers that implemented OAuth 2.0 without OIDC could not be configured through discovery metadata.

**Why it matters:** The change expands compatibility with enterprise authorization servers without requiring teams to misrepresent them as OIDC providers or hand-wire endpoint metadata.

**Platform impact:** Identity integration tests should verify issuer and endpoint metadata, key rotation, token audience, inbound validation, outbound credential flows, and failure behavior rather than treating discovery success as authorization correctness.

**Recommended action:** Connect one non-OIDC OAuth authorization server in a sandbox and test metadata refresh, key rotation, invalid issuer and audience values, unavailable endpoints, and revoked credentials.

**Watchouts:** Metadata discovery improves compatibility but does not validate an authorization design, token scope, policy mapping, or revocation path by itself.

Sources: [src-04](https://aws.amazon.com/about-aws/whats-new/2026/11/bedrock-agentcore-oauth2-discovery/)

### Google releases Gemini Decision 1 and the Decisions API

**Status:** preview · **Event date:** 2026-11-11 · **Confidence:** high · **Score:** 17/21

**What changed:** The Decisions API evaluates typed yes/no, choice, and ordered-score questions and returns probabilities and confidence instead of generated prose. Google states that it produces zero output tokens and can evaluate independent questions over shared text, PDF, audio, image, or video input.

**Why it matters:** It makes probabilistic routing, scoring, and escalation a distinct API primitive rather than a prompt that generates JSON for application code to parse.

**Platform impact:** Bedrock-centered teams can test the same architecture with classifiers or constrained model calls: keep thresholds, authorization, and composite policy deterministic while treating model confidence as an input rather than a decision authority.

**Recommended action:** Build a 500-case calibration set for one routing or escalation decision and compare probability calibration, false automation, abstention rate, latency, and cost with the current generative classifier.

**Watchouts:** The API is v1beta, and calibrated probabilities still require workload-specific calibration. Confidence must not directly grant permissions or approve irreversible actions.

Sources: [src-07](https://ai.google.dev/gemini-api/docs/changelog.md.txt) [src-08](https://aistudio.google.com/docs/decisions-api)

### OpenAI Agents SDK alpha expands durable execution and interoperability

**Status:** open source · **Event date:** 2026-11-08 · **Confidence:** high · **Score:** 16/21

**What changed:** The alpha adds application-owned durable root sessions, reconciliation for uncertain tool effects, hosted File Search, Code Interpreter and Image Generation tools, context and completion hooks, observed-usage budgets, expanded MCP resources and prompts, native Agent2Agent adapters, and local execution. It also changes new environment write policy to strict and renames MCP approval modes.

**Why it matters:** The release exposes concrete design choices for durable state, side-effect recovery, budget admission, tool governance, and cross-agent interoperability that can be compared with AgentCore and Bedrock Managed Agents.

**Platform impact:** Teams testing the SDK need checkpoint compatibility, executor-policy, approval-mode, usage-accounting, child-agent, and hosted-tool regression coverage before upgrading alpha environments.

**Recommended action:** Use a disposable project to test session resume after an uncertain tool result, strict write boundaries, budget overrun behavior, MCP approvals, and one A2A exchange; do not migrate production workflows from the alpha alone.

**Watchouts:** The release is prerelease and contains breaking configuration changes. Its budgets are admission controls: an admitted request can exceed a limit, and child usage is excluded.

Sources: [src-09](https://github.com/openai/openai-agents-python/releases/tag/v0.24.0-alpha.7)

## Bring to work

### Retrieval boundary bake-off

Compare direct AgentCore Web Search, Web Answer, and the existing retrieval pipeline on a fixed current-information set.

- **Fit:** Direct fit for Bedrock and AgentCore applications that need current external evidence.
- **Effort:** medium
- **Next step:** Freeze 50 questions and score coverage, freshness, citation alignment, injection failures, p95 latency, and cost per supported answer.
- **Sources:** [src-01](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-bedrock-agentcore-web-search-api/)

### Runtime version control

Make AgentCore runtime generation an explicit, tested infrastructure choice.

- **Fit:** Direct fit for any AgentCore Runtime fleet or CI/CD path that creates new runtimes.
- **Effort:** low
- **Next step:** Inventory versions, pin platformVersion, replay one representative workload on V1 and V2, and document rollback.
- **Sources:** [src-02](https://aws.amazon.com/about-aws/whats-new/2026/11/new-agentcore-runtime-default/) [src-03](https://aws.amazon.com/blogs/machine-learning/run-agents-securely-and-efficiently-with-the-next-generation-agentcore-runtime/)

### MCP hostile-repository regression

Verify that read-only Git tools cannot execute repository-controlled programs or escape repository and network boundaries.

- **Fit:** Direct fit for AgentCore Gateway or any agent runtime exposing MCP Git, filesystem, or fetch servers.
- **Effort:** medium
- **Next step:** Patch exact versions, then run hostile .git/config, alternates, symlink or junction, redirect, IPv6, and private-address cases in isolation.
- **Sources:** [src-05](https://github.com/modelcontextprotocol/servers/releases/tag/v2.4.0) [src-06](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-6hqx-gqrx-c5r2)

### Decision calibration pilot

Evaluate typed probabilistic decisions against the current generative routing prompt.

- **Fit:** Transferable to Bedrock stacks for routing, escalation, moderation, and evaluation even though Google’s API is external.
- **Effort:** medium
- **Next step:** Label 500 cases and compare calibration error, false automation, abstention, latency, and cost; keep authorization deterministic.
- **Sources:** [src-07](https://ai.google.dev/gemini-api/docs/changelog.md.txt) [src-08](https://aistudio.google.com/docs/decisions-api)
